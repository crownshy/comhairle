# ADR-0074: Partial updates can set nullable columns to NULL

**Status:** proposed
**Date:** 2026-11-27

## Context

Update routes often take a `Partial<Model>` generated by `partially`, and `to_values` only writes
fields that are `Some`. Nullable columns were marked `#[partially(transparent)]`, so the
partial field was a single `Option` and `None` had to mean "leave it alone". Nothing could
clear a column. Conversation `launch_date` and `close_date` need clearing. Plain serde reads
a JSON `null` as the outer `None`, the same as a missing key.

An `UpdateMyModel` patch struct with `my_field: Option<Option<T>>` has the same problem, where
serde deserializes `null` into `None` and a "set to NULL" path cannot be distinguished from
"leave field alone" path.

The frontend already sends three distinct states: `JSON.stringify` drops `undefined` keys
and keeps `null`.

## Decision

**1. A clearable field is `Option<Option<T>>` on the partial.** Remove
`#[partially(transparent)]` from the base field so `partially` wraps it. `None` means skip,
`Some(None)` means set NULL, `Some(Some(v))` means set the value. `to_values` keeps its
`if let Some(value)` shape; sea_query binds an inner `None` as a typed NULL.

**2. The `nullable` serde helper reads null as Some(None).** Use
`#[serde(default, deserialize_with = "crate::models::nullable")]` on any `Option<Option<T>>`
field, such as a hand-written request body. On a partially model, put it on the base field
so it is copied to the partial.

**3. Models that use `nullable` + `Partial` should not derive `Deserialize`.** `partially` 0.2.1 copies
every field attribute onto the partial and has no field-level option to scope one to the
partial alone. On the base model the helper sees a plain `Option<T>`, so a JSON `null`
fails to deserialize. Base models are built from database rows via `FromRow`, never from
JSON, so dropping the derive removes that failure mode instead of leaving it latent.
`Serialize` still accepts the `#[serde]` attribute and ignores `deserialize_with`.

A custom `Patch<T>` enum was rejected. `partially` generates `if let Some(x) = partial.field`
and `partial.field.is_some()`, so every partial field must be an `Option`. An enum would
mean dropping or forking `partially` and hand-writing `Deserialize` and `JsonSchema`.

## Consequences

- Any nullable column can be made clearable through the existing update route by changing
  two attributes. No per-field setter functions.
- The OpenAPI schema marks these fields optional and nullable, so the generated zod client
  types them as `T | null | undefined`.
- A base model that adds `nullable` must drop `Deserialize`. If a model genuinely needs
  `Deserialize` from JSON, this pattern needs a field-level attribute in `partially` first.
- Fields that should never be cleared through an update keep `#[partially(transparent)]`.
